# 🎁 「資産に変わる7つの動き」プロンプト集 完全版

限定期間の最上位モデルを「消費」ではなく「資産」に変える、7つの作業用プロンプトです。

**受け取り方**: 下のコードブロックをコピーするか、このファイルをそのまま保存してください。

**使い方**: 使いたい動きのブロックをコピーして、そのまま貼り付け。【 】の中だけ自分の内容に書き換えてください。

## ①CLAUDE.md・環境の総点検

```text
あなたは私のAI作業環境の監査役です。プランモードで動き、実行はしないでください。

対象: CLAUDE.md（グローバル/プロジェクト両方）、フォルダ構成、権限設定、カスタム設定ファイル

やること:
1. 上記を全部読み、次の4分類で問題を洗い出す
   - 重複（同じ指示が複数箇所にある）
   - 矛盾（指示同士がぶつかっている）
   - 期限切れ（もう使っていないルール・終わったプロジェクトの記述）
   - 肥大化（1ファイルが長すぎる。CLAUDE.mdは200行未満が目安）
2. 問題ごとに「削除/統合/移動/書き換え」のどれを推奨するか明記する
3. 最後に「最適化プラン」を優先度順の番号付きリストで出す

禁止事項:
- 私の承認なしにファイルを書き換えること
- 「ついで」の改善提案で本題を薄めること

出力形式: ①現状の健康診断サマリ（5行以内） ②問題リスト（分類・場所・推奨対応） ③優先度順の実行プラン
```

## ②Skillsの棚卸しとブラッシュアップ

```text
あなたは私のSkill資産の棚卸し担当です。

対象: 私のSkill（スラッシュコマンド / SKILL.md）一式

やること:
1. 全Skillを次の3分類に仕分けする
   - 現役: 直近1ヶ月で使った・今後も使う
   - 要改修: 使うが、指示が細かすぎる／検証工程がない／古いモデル向けの記述が残っている
   - 削除候補: 重複している・もう使っていない
2. 「要改修」のSkillごとに改訂案を出す。方針は次の2つだけ:
   - 指示を減らす（手順を細かく縛るより、ゴールと品質基準を渡す）
   - 検証を足す（作ったら動かして確かめる工程。できれば別エージェントのチェックも）
3. 改訂は1Skillずつ提示し、私の承認を得てから反映する

出力形式: 仕分け表 → 削除候補の確認リスト → 要改修Skillの改訂案（1つずつ）
```

## ③諦めた自動化への再挑戦

```text
昔挑戦して諦めた自動化に、いまのあなたの能力で再挑戦してほしい。

自動化したいこと: 【例: 毎朝、業界ニュースを集めて要約をSlackに投稿する】
前回諦めた理由: 【例: 記事の取得が不安定で、要約の品質もばらついた】

進め方（必ずこの順で）:
1. 全体設計: 処理の流れ・必要なツール・失敗しやすい箇所を先に示す
2. 最小構成: まず一番小さく動く形を作る（機能は最低限でいい）
3. 動作確認: 実際に動かして結果を見せる。動かない場合は原因の切り分けから
4. 拡張: 動いてから機能を足す。1つ足すごとに動作確認

守ること:
- 一発で完成形を目指さない。「動く最小構成」を最優先
- 認証情報・APIキーはファイルに直書きしない
- 完成したら、使い方と失敗時の対処をREADMEに残す
```

## ④自分用アプリの積年バグ退治

```text
あなたはこのプロジェクトのバグハンターです。

対象: 【リポジトリ / フォルダのパス】

やること:
1. コードベース全体を調べ、「前から直っていない不具合・怪しい箇所」を洗い出す
   - 放置されたTODO/FIXME、握りつぶされているエラー、再現条件不明のまま止まっている問題も対象
2. 見つけた問題を「再現手順・影響・原因の仮説」つきで重要度順に一覧化する
3. 私が選んだ問題から修正に入る。修正前に方針を出して承認を待つこと
4. 修正したら必ず実際に動かして検証する。「たぶん直った」で報告しない

出力形式: 問題一覧（重要度順） → 私の選択待ち → 修正方針 → 修正 → 検証結果
```

## ⑤メモリのブートストラップ（教訓の移植）

```text
あなたのメモリを「私専用」に育て直します。

やること:
1. これまでのセッション履歴を振り返り、次の2種類を抽出する
   - 私から受けた修正・注意（同じ指摘を2回以上受けたものは最優先）
   - うまくいった進め方・私が好む出力の型
2. 抽出した教訓をメモリに保存する。ルール:
   - 1ファイル1件、冒頭に1行要約
   - 「なぜそうするのか」の理由も書く
   - すでにある教訓と重複したら、新規作成せず既存を更新する
3. あわせて既存メモリを点検し、間違っているもの・古くなったものは削除または修正する

最後に: 保存した教訓の一覧と、削除・更新したメモリの一覧を報告してください
```

## ⑥MCPの一斉修理

```text
接続しているMCP（外部ツール連携）の総点検をお願いします。

やること:
1. 設定されているMCPサーバーを一覧化し、次の3分類に仕分けする
   - 正常: ツールを1回実際に呼んで成功を確認できたもの
   - 故障: エラーが出るもの（エラーメッセージを添える）
   - 休眠: 接続はできるが、直近1ヶ月使っていないもの
2. 「故障」はエラーログから原因を切り分ける（認証切れ／設定ミス／サービス側の障害／課金切れ）
3. 直せるものは修正手順を提示 → 私の承認後に修正 → 実際にツールを呼んで成功を確認
4. 「休眠」は削除候補として提示（判断は私がする）

守ること: 認証の再設定が必要な場合は、値を聞き出すのではなく「どこで何を発行すればいいか」の手順を示す
```

## ⑦制作フローのSkill化（LP・広告・スライド）

```text
単発の制作依頼を「再利用できる制作ライン」に変えたい。

対象の制作物: 【例: セミナースライド / LP / 広告バナー / note記事】

やること:
1. デザイン規約の正典化: 色・フォント・レイアウトの型を1つのファイルにまとめる（今後の全制作がこれを参照する）
2. フローの設計: 「構成を渡す → 同じ体裁で生成 → 自動検証 → 別エージェントのダブルチェック → 修正反映」の流れをSkillとして書く
3. 検証の自動化: はみ出し・誤字・規約違反を機械的にチェックする仕組みを含める
4. 試運転: 実際に1本作ってフローの穴を見つけ、Skillに反映する

ゴール: 次回から「構成を渡すだけ」で同じ品質の制作物が出てくる状態
```

**ポイント**: ①と⑥から始めると、残りの動きすべての効率が上がります。実行系は必ずプラン（計画）を確認してから承認を。
